## 排查：登出接口 curruser / CurrentUser 为 null
- 现象：调用 `POST api/User/Logout` 时 `BaseController.CurrentUser` 为 null，导致 `LogoutCommand` 字段全空。
- token 本身正常（sub=50, name=test1, jti=..., exp=2026-08-01，未过期），[Authorize] 已通过，问题不在 token。
- 根因：`D:\ljx codes\DDD.FE\1.Open\Open\Open\Controllers\BaseController.cs` 在**构造函数**里读取 `HttpContext.User`，但 ASP.NET Core 控制器构造时 `HttpContext.User`（ClaimsPrincipal）尚未被认证中间件填充，故 `User` 为 null，`if (User != null)` 整段跳过，`CurrentUser` 保持 `default!`(null)。
- 修复方向（用户要求不改代码，仅提供方案）：把拼 CurrentUser 的逻辑挪到 `OnActionExecuting`（实现 IActionFilter）或注入 `IHttpContextAccessor` 用计算属性；并加 `IsAuthenticated` 守卫。

## 最终落地方案：独立 CurrentUserFilter（IActionFilter）
- 新建 `1.Open/Open/Open/Filters/CurrentUserFilter.cs`（namespace Open.Filters，实现 IActionFilter）。
- 在 `OnActionExecuting` 中用 `context.HttpContext.User`（已认证）解析 Userid/Username/Jti，写入 `((BaseController)context.Controller).CurrentUser`。
- 注册：`Program.cs` 改为 `builder.Services.AddControllers(o => o.Filters.Add<CurrentUserFilter>());`（加 `using Open.Filters;`）。
- `BaseController` 不再实现 IActionFilter，只保留 `public CurrentUser? CurrentUser { get; set; }`。
- 优势：避免把过滤器方法写在控制器上导致 MVC 把它当 action 发现（曾出现 `OnActionExecutionAsync` 多个 FromBody 参数的 InvalidOperationException）。

- 分层与依赖方向：**正确**，符合 DDD 依赖倒置。Domain 不依赖任何层；Application 只依赖 Domain+Shared；Infrastructure 依赖 Application（实现其抽象接口）；Open(Web) 作为组合根依赖 Application+Infrastructure。无上层引用下层。
