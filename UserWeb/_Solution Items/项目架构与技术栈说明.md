# DDD.FE 项目架构与技术栈说明

> 文档生成时间：2026-08-09
> 适用代码版本：当前仓库主线（含 API 文档 / 我要充值 / 订单号不省略等近期改动）

---

## 1. 项目概览

DDD.FE 是一套**社交媒体增长服务平台的用户端系统**，提供「下单、查单、消费记录、联系客服、代理管理、开放 API」等能力。整体采用**前后端分离**架构：

- **后端**：基于 .NET 8 的 Web API，使用 DDD（领域驱动设计）+ CQRS 分层，承载业务逻辑、鉴权、计费等核心能力。
- **前端**：基于 Vue 3 + Vite 的单页应用（SPA），面向终端用户，强调移动端优先与响应式体验。
- **部署**：Docker Compose 编排，后端 API 容器 + 前端 Nginx 静态站点，数据库/缓存复用宿主机原生 MySQL/Redis。

## 3. 后端架构（分层依赖）

```
1.Open (Host/API 控制器)
   └─> 2.Application (CQRS: Command/Query + Handler + Validator)
          ├─> 4.Domain (实体/聚合/领域规则，零依赖)
          └─> 5.Shared (工具类/通用基类型，全员引用)
   └─> 3.Infrastructure (EF 仓储/DB 上下文/外部集成)
          ├─> 4.Domain
          └─> 5.Shared
```

依赖铁律：
- **Domain 零依赖**，不引用 Application / Infrastructure / Shared 之外的任何项目。
- **Shared 被所有层引用**（统一命名空间 `Shared.Utilities`）。
- Application 定义契约（Contracts）与处理器（Handlers），Infrastructure 提供实现（Repository、DbContext）。

### 3.1 关键设计点
- **CQRS 组织**：`Events/{领域}/Contracts/{Commands|Queries}` + `Handlers/{Commands|Queries}`，契约即入参/出参 DTO。
- **DTO 目录规范**：`Common/Models/Request/{领域}/*Request` 与 `Common/Models/Response/{领域}/*Response` 严格分离，一眼可辨用途。
- **分页基类**：`PagedQuery`（PageIndex 默认 1 / PageSize 默认 20），返回带总数的列表须显式 `new ApiResult<List<T>>{Data, DataTotal}`。
- **金额精度**：统一 `Shared.Utilities.Utils.RoundToSixDecimals(decimal)`。
- **单号生成**：`Utils.GenerateSerialNo("O"/"W"/"C"/"T")`，在 Handler 内生成后传入实体构造函数（契约不留单号字段，防伪造）。

## 4. 前端架构

```
src/
├─ api/            # 后端接口封装（user/order/config/notice/ticket/apiKey…）
├─ assets/js/      # iconUtils 等工具
├─ components/     # 公共组件（DraggableWechatButton、ChangePasswordModal、icons）
├─ stores/         # Pinia（auth.js 等）
├─ router/         # 路由表与守卫
├─ utils/          # 格式化（format.js）
├─ views/          # 页面（homeIndex/orderIndex/consumptionIndex/ticketIndex/apiDocs…）
└─ App.vue / main.js
```

### 4.1 关键约定
- **Token 存储**：`localStorage.flowengine_token`，HTTP 拦截器自动附加 `Bearer`。
- **401 处理**：状态码判 401 → 清 token + 跳 `/login?reason=expired`。
- **响应式双布局**：桌面 `Table`（`scroll.x≥768`），移动端（`<768`）卡片；经 `window.resize` 监听 `isMobile`。
- **枚举同步**：状态/类型下拉统一从 `enumApi` 同步，页面不再硬编码。
- **API 文档页**：内置「生成/查看 API Key」双按钮，JWT 自动复制，调用订单/余额/配置接口说明。

## 5. 数据与基础设施

- **数据库**：MySQL（`ddd_flowenginedb`），EF Core Code First 映射，Pomelo 驱动。
  - 软删除审计：`tk_user`、`tk_comment` 两表用 `IsDelete + DeleteTime`，**禁止 `DateTimeOffset.MinValue`**（低于 MySQL DATETIME 下限）。
  - 时间型列改造须「加新列→搬数据→删旧列→改名」，不能直接 MODIFY。
- **缓存/限流**：Redis 存登录 jti（登出删），滑动窗口限流（授权用户 200 次/30s，按 `userid:jti` 计）。
- **持久化卷**：用户上传图片（工单截图、客服微信图）落在 Docker 命名卷 `uploads`（`/app/wwwroot/images`）。

## 6. 安全设计

| 维度 | 措施 |
|---|---|
| 认证 | JWT Bearer；API Key 即「该用户 20 年期 JWT」，`client_type=API` 写入载荷 |
| 授权 | `[Authorize]` + 角色（Agent）；当前用户统一经 `ICurrentUser` 注入取 `Userid` |
| 防 IDOR | 契约删除服务端注入的 UserId 字段；需鉴权 Handler 顶部加 `if(!currentUser.IsAuthenticated||Userid<=0) return UnAuth()` |
| 防伪造 | 单号服务端生成，不信任客户端传入 |
| 金额安全 | Validator + 领域方法双校验；日志禁打密钥/密码/Token |
| 传输 | 生产建议前置 Nginx 终结 TLS；当前 API 暴露 9080、前端 80 |

## 7. 部署架构（Docker Compose）

```
+-------------------+        +-------------------------+
|   浏览器 / 手机    | <----> |  Nginx (web:80)          |
+-------------------+        |  挂载 ./web/dist (SPA)   |
                             +-----------+-------------+
                                         | /api 反向代理
                                         v
                             +-----------+-------------+
                             |  ddd-api (api:9080->8080)|
                             |  ASP.NET Core 8          |
                             |  连接宿主机 MySQL/Redis   |
                             |  (host.docker.internal)  |
                             +-----------+-------------+
                                         |
                      +------------------+------------------+
                      | 宿主机原生 MySQL  │ 宿主机原生 Redis   |
                      | ddd_flowenginedb │ 6379              |
                      +------------------+------------------+
```

要点：
- `api` 服务从 `./publish` 构建单阶段运行时镜像（复用本地 `dotnet publish -r linux-x64` 产物），依赖已缓存的 `aspnet:8.0`。
- `web` 服务用 `nginx:alpine`，绑定挂载 `./web/dist` 与 `./web/nginx.conf`。
- 运行时配置（连接串、JWT 密钥、限流）通过 `Section__Key` 环境变量注入，**`appsettings.json` 已被 `.dockerignore` 排除**。
- 上线前须收紧 CORS（当前 `AllowAnyOrigin` 仅适合联调）。

## 9. 已知约定与坑（来自实战）

1. **分页总数**：返回带总数列表勿用 `Successed(items,total)`（对 IList 会按 Count 覆盖 `DataTotal`），须显式构造 `ApiResult<List<T>>`。
2. **实体字段非空**：int/string/枚举一律非空，实体定义不允许 `?`；string=`default!`，数值默认 0，DateTime 由构造赋。
3. **路由**：方法显式 `[HttpPost("动作名")]`，禁止控制器级 `[action]` token。
4. **本地构建**：Windows 发布 Linux 容器必须 `dotnet publish -r linux-x64 --no-self-contained`，否则镜像跑不起来。
5. **sandbox 删除限制**：本机沙箱拦截一切删除，Python 加 `-S` 可绕过；Git Bash 路径用 `D:/...` 正斜杠。
6. **前端 env**：`.env.development` 与 `.env.production` 当前均指向服务器 `http://49.234.58.209:9080/api/`；本地调试需改回 `localhost` 并重启 vite。

## 10. 可优化方向（建议）

- **前端 chunk 体积**：`index` 主包 >1MB，可进一步路由级懒加载或拆 vendor。
- **CORS 收紧**：生产环境应配置白名单而非 `AllowAnyOrigin`。
- **安全项（用户确认暂不修）**：`appsettings` 明文机密、Argon2id 全局固定盐，后续可迁移至密钥管理。
- **DTO 一致性**：部分历史契约仍混用旧命名，可随迭代继续收口到 Request/Response 规范。
- **API 文档**：可补充独立订单详情接口（当前以列表 keyword 查询替代）。
